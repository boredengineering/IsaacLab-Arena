## Control helper HTTP (same-origin /control, independent of Arena)

- POST /control/session: JSON `{pairing_token: string}` for initial pairing; `{}` recovers a valid control cookie. Response exact `{schema_version:1, csrf_token:string, expires_at:number}`. Cookie HttpOnly/SameSite=Strict/Path=/control. Never return/store pairing token; JSON/Host/Origin checks apply. CSRF for authenticated mutations.
- DELETE /control/session: CSRF mutation, response `{schema_version:1, revoked:true}`.
- GET /control/research-services, optional `request_id` query: authenticated observation, no starts/protocol work. Exact response `{schema_version:1, profile_revision:string, expected_policy:string, services:Service[], api:string, startup_allowed:boolean, operation:Operation|null}`. Services exactly arena,neo4j,gr00t ordered; Service exact `{id:string,status:string}`. Status running/stopped/missing/mismatch/unknown. API healthy/stopped/unavailable/unknown. Expected policy fixed approved public model label.
- POST /control/research-services/start: exact `{request_id:string,profile_revision:string}`; request ID lowercase 32hex, profile revision lowercase64hex; CSRF mutation. 202 (or same accepted replay) response is Operation. Operation exact `{request_id:string,profile_revision:string,status:string,code:string}`. Status starting/completed/failed/unknown. Static code allowlist: starting,services_started,start_failed,start_unknown,profile_mismatch,resource_unavailable,api_unavailable. Completed means approved services/API startup only, NOT model/graph/simulation acceptance.
- GET with request_id returns exact retained operation or 404; no latest substitution. One current operation with bounded retained receipt history. Unknown acceptance is GET/reconciliation, no blind reissue. Strict malformed/extra-field rejection; bounded request/response/errors. Authentication errors 401/403, conflicts409, busy429, private failures503. Public errors only `{error:static_code}`.

Helper/backend public profiles must not contain credentials, raw Docker environments/commands, arbitrary filesystem paths or pairing material. Parent reviews exact operator-only profile format implemented by helper before provisioning. Install trusted helper bytes independently of mutable checkout; no Docker socket in application/frontend.

## Codec contract (policy producer/native consumer)

### Raw safety preflight (review-blocker integration)

Parent API integration adds `native_array_metadata(raw_array, *, max_array_bytes=...) -> {shape, dtype, bytes}` without allocating arrays. It shares the same NPY/current-wrapper validation used by `preflight_native_message`, rather than maintaining a second legacy parser. The API codec reply path first applies a 4096-byte message and 34-byte aggregate probe-array budget, then checks the exact numeric/image layouts before calling the actual native decoder. Tests cover legacy N1.6 bytes, malformed allocation headers, wrong shape and the release's non-null action-config native/wire digest roundtrip. Configuration representation is preserved: N1.6 DROID's internal arm action representation is RELATIVE, not evidence that the final Arena action adapter should be changed to relative joints.

Core SDK-free `isaaclab_arena.agentic_environment_generation.policy_contract` now exports `preflight_native_message(payload: bytes, *, max_bytes=67108864, max_array_bytes=67108864) -> raw plain MessagePack tree` and `safe_decode_native_message(payload, decoder, **limits) -> decoder result`. Backend MUST call preflight BEFORE native `from_bytes`, `np.load`, msgpack-numpy object hooks or any array allocation. It supports legacy N1.6 `__ndarray_class__/as_npy` NPY v1/v2/v3 and current msgpack-numpy numeric array/scalar wrappers; exact payload-length, numeric dtype, shape, aggregate allocation and structure bounds; no pickle/object/structured dtype or extensions. Caller can use smaller readiness/codec limits. Preflight does NOT decode arrays; backend still needs both wire decoder forms after validation. Native socket receive wrappers will apply this same preflight on server and client before existing serializer hooks.

Provenance scope correction: `config_sha256` covers only allowlisted **model-directory** data/config bytes (including N1.6 root-level statistics.json and embodiment_id.json alongside processor_config.json; Gr00tPolicy passes model_dir directly to AutoProcessor.from_pretrained). It does NOT cover runtime Eagle processor/tokenizer/backbone config, SDK code, or the whole runtime. N1.6 commit `ead52833afbbf4243f8cd5e7664f48a94de03b19` processing_gr00t_n1d6.py:49-53 and modules/eagle_backbone.py load their separate `gr00t/model/modules/nvidia/Eagle-Block2A-2B-v2` directory. That installed runtime must be independently trusted/pinned. Do not describe model-dir hash approval as complete config/runtime verification.

- First-party module: `isaaclab_arena_gr00t.policy.serving_metadata`. Exports `make_codec_probe()`, `validate_codec_probe(probe)`, `validate_codec_echo(response, probe, expected_server_info)`, `native_serializer_sha256()`, `verify_native_connection(client, expected_server_info)`, and `VerifiedPolicyClient(expected_server_info=..., host=..., port=..., strict=False)`. SDK-free structural functions remain in core `policy_contract.py`.
- Wire request uses the actual imported `gr00t.policy.server_client.MsgSerializer`: `{endpoint:'codec_echo',data:{probe:{nonce:32hex,numeric:float32 ndarray shape(1,4),image:uint8 ndarray shape(1,2,3,3)}}}`. `make_codec_probe()` uses fresh random nonce, numeric `[[0,-1.5,2.25,17]]`, image `arange(18).reshape(1,2,3,3)`. Response exact `{server_info:<exact v1 metadata>,probe:<same nonce/dtype/shape/bytes>}`. Probe and response each <=4096 native-encoded bytes; reject unknown fields, non-finite/object arrays, wrong shape/dtype/bytes, changed identity. No action/reset/kill occurs in the helper.
- `verify_native_connection` checks actual local serializer source hash, exact ping `{status:'ok',message:'Server is running'}`, exact pinned get_server_info, normalized get_modality_config digest, fresh codec_echo, and exact pinned get_server_info again, in that order. Caller owns bounded native client/deadlines/cleanup. Backend readiness must use native codec in its isolated worker; metadata-only plain msgpack success is not native transport verification.
- `serializer_sha256` hashes bytes of the module actually defining imported MsgSerializer (not a version/name). `modalities_sha256` uses `canonical_metadata_digest(normalize_modalities(...))`. JSON canonicalization is UTF-8, sorted keys, compact separators, ensure_ascii=False, allow_nan=False; null optional ModalityConfig fields omitted, non-null action/normalization fields retained and Enum names normalized. N1.6 language key is `annotation.language.language_instruction`, proven by vendored git tag `n1.6-release:gr00t/configs/data/embodiment_configs.py`'s `oxe_droid` entry; bare `language_instruction` is not the native modality key.
- Native config `expected_server_info=None` preserves legacy, explicitly unverified behavior. With a pin, `VerifiedPolicyClient.ensure_verified_connection()` performs the full five-RPC codec/metadata handshake once per owned socket; recovery invalidates that cache. `verify_identity()` checks pinned metadata with one RPC thereafter, falling back to a full handshake on a replaced socket. `verify_policy_identity(client, expected_server_info)` is the uncached shared lightweight helper. Fresh native inference has pre/post identity checks; Arena adds its final release check after translation/scheduling. Exact budgets: initial connection five RPCs (reuse verified native modalities), fresh Arena action four RPCs total (three metadata + one inference), buffered release one metadata RPC. Drift on connect, fresh, buffered or reconnect fails closed. Metadata endpoints default 3000ms, configurable 1–5000ms; native inference defaults 15000ms, independently configurable 1–300000ms via timeout_ms / Arena remote_timeout_ms. Native timeout socket replacement closes the old socket with linger=0 and reinstalls bounds; no automatic inference retry. Never upgrade a pin from server-reported values. First-party OwnedPolicyServer reuses native dispatch/endpoint hooks, owns N1.6-compatible context-manager/close, and applies the same raw receive preflight before native decode. Verified client also owns close and timeout recovery; neither assumes modern SDK lifecycle methods.
- Serving CLI: `python -m isaaclab_arena_gr00t.policy.serving_metadata --model-path <materialized-local-model> --checkpoint-sha256 <operator-pin> --config-sha256 <operator-pin>`. `--fingerprint-only` reads artifacts and prints candidate hashes without loading/binding; it is not independent operator approval. HF_HUB_OFFLINE and TRANSFORMERS_OFFLINE forced before lazy model imports. Native Gr00tPolicy loads the exact directory before the same native PolicyServer is created and extended via register_endpoint. Manifest hashes cover sorted `{path,size,sha256}` records in `{files:[...]}`: checkpoint=safetensors files; config=allowlisted config/tokenizer/processor bytes. Before/after-load manifests must agree. Unknown files (including .env), symlinks and special files fail closed before reads. Requires a trusted immutable local model mount and compatible N1.6 runtime; no loaded-model/GPU/inference or live server validation was authorized by implementation tests. No hardware attestation claim.

## Readiness PASS-admission clarification (additive v2 contract)

- The v2 POST model additionally accepts `check_provider?: boolean`, strictly literal, default **false**. GET, v1 `{}`, and ordinary v2 checks never call a generation provider. This field is explicit consent for the following bounded authenticated **metadata GET only**, not inference. It is not a credential/key, URL, model, GPU budget or device selector supplied by the browser. Existing prompt/YAML/document validation and source/configuration fences remain in force.
- Only exact pairs admitted by the existing `resolve_inference_profile` catalogue at official `https://api.openai.com/v1` (or its already-supported single trailing slash) are eligible: currently `gpt-4.1` and `gpt-6-astra`. Other providers, custom endpoints, guessed aliases and undocumented models yield `generation_provider_unsupported` without constructing an HTTP client. [Official model retrieval](https://developers.openai.com/api/reference/resources/models/methods/retrieve/) specifies `GET /v1/models/{model}` and a model object with `id` and `object: 'model'`. Readiness requires exact returned model ID and object literal, rejecting duplicate JSON keys; it does not substitute a configured label for authenticated evidence.
- The existing private ModelSettings session reference (including its credential generation) or current explicit server configuration is resolved through the same boundary used by WorkflowAuthorization capture; readiness does **not** call capture or issue grants/journal work. Only the private worker stdin carries provider/graph credentials. Current session authority, current credential reference and exact private configuration are compared again before releasing completion. Same-key replacement, expiry, Forget and changed server configuration retire earlier provider PASS. No provider SDK/Agent, chat/completion, initialization ping, dotenv lookup or inference is used. HTTPX uses verified HTTPS, no environment proxy/CA overrides, no redirects and no retries; only the official fixed model GET is sent.
- Provider responses are at most 8192 raw bytes; compressed bodies are refused, error/redirect bodies are not consumed or exposed. Socket operations use a two-second timeout with a four-second checked elapsed read budget inside the existing **12-second hard private-worker deadline**, including all requested dependencies. Only static codes cross the pipe: `generation_model_readable`, `generation_provider_unsupported`, `generation_provider_unavailable`, `generation_authentication_failed`, `generation_permission_denied`, `generation_model_missing`, `generation_rate_limited`, `generation_redirect_refused`, `generation_model_mismatch`, `generation_metadata_invalid`, `generation_check_timeout`; existing `generation_not_configured`/`configuration_changed` remain. HTTP 429 is rate/quota-limited **unknown**, never proof of available quota; model-read success does not prove inference permissions, quota, structured output, prompt generation or task success.
- Build and A2 resource PASS requires server-only explicit `ARENA_WORKBENCH_GPU_MIN_FREE_MIB` (positive decimal MiB, no default budget) and optional exact `ARENA_WORKBENCH_GPU_UUID` (`GPU-` plus full UUID, no prefix matching). The API must be provisioned with these environment values by the trusted operator/helper; the follow-up does not modify helper allowlists or Docker. Missing budget is `resource_unknown`, not an always-false placeholder: an existing owned lease plus observed sufficient visible-device headroom can pass.
- The probe opens **the execution path's existing** `snapshot_process.GPU_LEASE` (normally `/eval/.arena-workbench-gpu.lock`, server override `ARENA_WORKBENCH_GPU_LEASE`) read-only, no-follow and nonblocking. It requires an existing regular file owned by the same non-root runtime user. A transient shared/nonblocking flock checks actual cross-container contention while sampling; it never creates/writes the lease, changes file mode/ownership/content or takes the exclusive job lease. An absent lease requires separate approved operator provisioning or a previously initialized execution lease; Check does not initialize it. Contention is `resource_lease_busy`. Lease replacement during the read invalidates admission.
- Bounded `nvidia-smi --query-gpu=index,uuid,memory.free,memory.total,mig.mode.current --format=csv,noheader,nounits` reads (16384 bytes each, one shared three-second deadline) must select the same visible device in two samples, with both free-memory observations meeting the explicit budget. `CUDA_VISIBLE_DEVICES` and `NVIDIA_VISIBLE_DEVICES` are preserved into the private worker and metadata subprocess and checked against the frozen private inputs. Hidden devices never pass; malformed/missing metadata, enabled/unknown MIG partitioning, ambiguous CUDA ordinal mapping, multiple eligible devices without an exact pin, insufficient headroom and device changes fail closed. Exact UUID visibility is preferred; CUDA ordinal `0` is accepted only after an already-singleton physical selection. The UUID pin selects observation, **does not change runtime CUDA device selection**. Operators must align the execution visibility with their intended GPU.
- Resource codes are `resource_headroom_observed`, `resource_unknown`, `resource_lease_busy`, `resource_insufficient`, `resource_device_changed`, `resource_hidden`, `resource_ambiguous`; parent-side changed budget/visibility uses `configuration_changed`. Resource PASS is point-in-time observed GPU headroom, not a reservation, OOM-immunity claim, RAM/PID check or simulation guarantee. Other processes can consume memory immediately afterward; execution retains its own lease/admission gates.
- Full `a2_gr00t` now requires the Neo4j worker's **actual existing retriever read** of the explicit configured database, in addition to runtime, policy identity/protocol/transport and GPU evidence. Empty/structural/measured describe read outcomes, not generated research success. A2 is existing-draft evaluation dependency readiness: generation is a separate phase unless `check_provider:true`, which makes `generation_model` required as an additional requested read. Graph generation always requires that model check, so ordinary graph-generation Check retains `generation_configuration_only`/unverified and `ready:false`; opt-in authenticated metadata can satisfy this read gate. Build does not require graph/policy or generation unless provider reading is requested.
- `ready` means **all requested dependency/read checks passed at observation time**. It does not mean full-stack inference/physical acceptance, authorize execution/publication, prove source-scene validity beyond existing input validation, or certify future prior consumption. Policy evidence still says `inference:'not_run'`. The separate bounded policy-smoke job/effect/receipt contract remains **unfinished**, awaiting frontend approval; no synchronous/unbounded policy smoke or weakened policy validation was added. Native N1.6 raw-policy consumer integration is owned separately by the parent/policy owner and must be independently verified.
- Public response fields/statuses remain unchanged; the new literal codes are exported in `readiness.READINESS_CODES`. Frontend code-allowlist/explicit provider-consent UI and helper environment provisioning are parent integration work, not silently implemented or tested by this backend owner.

## Guarded policy effect call (first-party v1)

- The **new, unreleased first-party v1 serving contract includes `verified_call`**. No `get_server_info` fields or schema version change. A peer without this endpoint is unsupported for verified effects and fails closed; there is no automatic retry, legacy fallback, or repinning. Legacy native `get_action`/`reset` registrations remain unchanged for legacy unverified clients.
- Native wire: `{endpoint:'verified_call',data:{expected_server_info:<exact detached private v1 pin>,endpoint:'get_action'|'reset',data:<original effect data>}}`. The guarded argument object has exactly `expected_server_info`, `endpoint`, `data`. Only the two literal effect names are accepted; metadata, kill, recursive guarded calls and unknown names are rejected. `get_action` data is exactly `{observation:dict,options:dict|null}`; `reset` data is exactly `{options:dict|null}`. Missing/extra fields, malformed types and invalid/extra/mismatched pin fields fail before any effect. Observation contents and option contents retain native policy semantics.
- The same native server registers the guarded handler. It strictly validates the pin and compares it with its currently bound `get_server_info()` before invoking that bound policy's native `get_action` or `reset` handler once. The metadata helper rechecks the same policy/model/processor objects, modality digest and serializer digest. Native server dispatch is serial: the receiving-instance check and effect happen in one request, closing peer replacement between a successful metadata RPC and the subsequent effect RPC. This is trusted local server provenance, not protection against hostile in-process mutation or hardware attestation.
- `VerifiedPolicyClient.call_endpoint` transparently intercepts both effects, carrying a fresh detached copy of its private pin and the original data. It chooses deadlines from the **original** effect before changing the wire endpoint: inference uses the configurable native inference deadline, reset retains the metadata deadline. Existing pre/post/final metadata checks, shared RLock, timeout socket cleanup and verification-cache invalidation remain. Five initial handshake RPCs, four steady fresh Arena-action RPCs, one buffered-release RPC; the guard adds no round trip. Existing native `_get_action` response semantics are unchanged.
- Readiness still sends no effects; metadata/codec success alone does not test guarded dispatch or authorize inference. Offline regressions use actual native client serialization/server dispatch over inert sockets with fake effects. Replacement after metadata produces zero fake action/reset invocations; valid pins dispatch once, malformed requests and older peers fail closed. No live model, service, GPU, database or rollout acceptance is claimed.
