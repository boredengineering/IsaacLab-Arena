## 1. The Gap This Session Closed

The env-generation graph modelled the *scene* — entities, poses, reified spatial relations — and nothing about the *policy*. So the pipeline could autonomously build a scene and then evaluate a checkpoint that had no chance of operating in it, with no representation of why. Every model-side conclusion from sessions `g1autopsy`, `depthaudit`, and `c1blockers` lived in prose, not in the graph, and therefore could not drive a decision.

The load-bearing addition is `arena:violatesInvariant`, joining an `arena:EnvironmentGraph` to an `arena:TrainingInvariant` asserted by the corpus a policy was trained on. That single edge is what lets a query ask "why should this policy be expected to fail here" and get an answer with a magnitude attached.

## 2. Pathway C: Sequential Success Gate

- `SuccessMode.SEQUENCE` added to `isaaclab_arena/tasks/terminations.py`. Predicates latch in listed order; a later stage cannot latch until every earlier one has. Concurrent stages cascade within a step, so genuinely simultaneous predicates still behave like `ALL`.
- `EpisodeScopedState` (`isaaclab_arena/tasks/predicates/episode_state.py`) provides the per-env latch and running-minimum slots, self-clearing when `episode_length_buf` rewinds. Detecting the boundary from the env's own step counter — rather than a reset event — keeps it correct whether or not progress tracking is wired up, and idempotent under repeated evaluation within a step.
- `object_lifted_above_resting_min` (`predicates/spatial.py`) references a per-env running minimum of the object's own height. Deliberately *not* `object_is_above_height(use_settled_state=True)`: that depends on the rest-pose recorder, which only the progress tracker resets, so using it in the always-active termination path would have made success unreachable whenever progress tracking was off.
- `PickAndPlaceTask` gained `require_lift_before_place=True` and `min_lift_height=0.05`. Both pass through `TaskSpec.params` with no extra plumbing, so generated envs can set them from YAML.

**Consequence worth remembering**: six existing tests reach success by *dropping* an object into its destination under zero actions. They test contact-sensor plumbing, not manipulation, and now pass `require_lift_before_place=False` with a comment saying why. If a future test asserts success without a grasp, that flag is the reason.

## 3. Model-Side Graph

- `ontology/arena_policy_diagnostics.ttl` — `Policy`, `PolicyArchitecture`, `DemonstrationCorpus`, `TrainingInvariant`, `SimToRealInvariant`, `DistributionShift`, `FailureMode`, `DiagnosticTechnique`, `ActivationProbe`, `RemediationTechnique`, `ProbeObservation`, and the properties joining them.
- `policy_capability_graph.py` — three closed registries (14 failure modes, 15 diagnostic techniques, 17 remediations), the `GN1x-Tuned-Arena-G1-Static-PickNPlace` profile with its six corpus invariants, shift measurement off the spec, Bayesian belief update, and the planner.
- `policy_diagnostics_sync.py` — RDF emission plus the Neo4j LPG mirror, with SPARQL for blocking-shift-to-remediation joins.

Two relationships that carry the judgement calls from earlier sessions:

- `arena:discriminates` (technique → failure mode) makes technique choice an information-gain calculation instead of running the whole battery. `select_next_diagnostic` maximises entropy reduction per unit cost, gated by what is actually runnable — activation probes need in-process weights, so they are never offered against a remote ZMQ server.
- `arena:invalidatedBy` (remediation → invariant) keeps friction inflation *in* the graph and permanently disqualified. It has efficacy 0.8 because it does work in simulation; that is precisely why it needed representing rather than omitting, so it stops being rediscovered.

`compress_action_chunk` carries efficacy 0.35, not the 0.92 severity the old oracle rule implied — the B1 v4 run cut conversion from 52% to 16% by compressing 16→8. The registry records the measurement, not the hypothesis.

## 4. Activation Probes

`policy_activation_probe.py` hooks GR00T N1.7 (`backbone`, `action_head.model.transformer_blocks`, `action_head.vlln`, `action_head.action_decoder`). GR00T runs attention through fused kernels that never materialise the attention matrix, so per-patch attention weights are not recoverable from a block's output. Two design consequences:

1. **Block conditioning delta** stands in for attention: `‖out − in‖ / ‖in‖` per block, bucketed into image cross-attention / text cross-attention / self-attention using `AlternateVLDiT`'s parity rule (odd = self-attend, even = cross-attend, every `2 * attend_text_every_n_blocks`-th = text). An image bucket far below the self-attention bucket means the trajectory is being generated with little reference to the camera.
2. **Ablation is the causal check** and is the strongest signal available: re-run inference with the image spatially permuted and measure the action delta, normalised by the policy's own sampling-noise floor. Near zero proves vision is unused; large proves the policy sees the scene and fails anyway. These need different fixes, and no behavioural metric separates them.

Two details that are easy to get wrong and were found the hard way:
- **Seed every comparison.** The flow-matching head starts from Gaussian noise, so two identical calls differ by construction. Unseeded, an ablation delta measures sampling noise.
- **Permute, do not mean-fill.** Filling with the image's own mean leaves every global statistic intact and is invisible to a policy that reads them — a test caught exactly this, returning a zero delta for a demonstrably vision-conditioned model. A permutation holds the intensity histogram fixed and removes only spatial layout.

## 6. Decision Encoded: Adapt the Model, Not the Scene

Sessions `c1blockers` rejected Pathways A and B. `RemediationTechnique.preserves_target_scene` encodes that: `reanchor_surface_to_corpus_height` and `mirror_layout_to_corpus_laterality` are marked `False`, so `select_remediation(preserve_target_scene=True)` excludes them. The planner reports both branches side by side, because choosing between them is a decision about what the benchmark measures, not an optimisation.

Under that constraint the honest ranking for `vertical_reach_ood` is short and unflattering: `cartesian_vertical_offset_adapter` (efficacy 0.35, cheap) then `collect_demos_and_finetune` (0.90, cost 8.0). `rank_remediations` exists so callers see this rather than only the cost-normalised argmax — a cheap low-efficacy fix outranks an expensive high-efficacy one on score even when the driving shift is far beyond what a config change can absorb.

**For the galileo-fine-tune-then-transfer plan**: after fine-tuning, register a *new* `PolicyProfile` whose invariants reflect the widened training distribution (notably a larger `surface_height_rel_pelvis` tolerance, or the axis dropped entirely if randomised). Transfer readiness against `maple_table` is then a re-measurement, not a re-argument.
