# Scenario walkthrough / mental-model check

Status: design-level tabletop exercise against `research-and-protocol.md`; independent consistency review passed with no blockers. These are reasoned traces of the proposed rules, NOT executed dashboard, provider, filesystem, database or simulator tests. The purpose is to expose contradictory ownership, missing decisions and unsafe recovery before implementation; it cannot prove runtime correctness.

## Method and stopping rule

For each case, follow (1) input/authorization, (2) attempt release, (3) durable evidence, (4) side effects, (5) failure/recovery, and (6) user-visible outcome. Stop the trace at unavailable evidence or authority rather than inventing success. The I1-I10 invariants are defined in the protocol appendix. A consistent trace still needs the listed fault/integration test during implementation.

## A2 reference journey

The operator opens New environment, enters the DROID banana-to-large-plate prompt and chooses the model, bounded Graph-RAG fallback policy and publication mode. The accepted request has no base YAML or document ID. This must hold even if another editor tab has an apple/bowl document open. The worker receives separate model and retrieval grants, captures the exact priors consumed, and produces a candidate receipt. The content is reviewed against the A2 registry/task contract; a structurally valid banana-to-bowl candidate is not accepted as A2.

For the explicit generate/version/publish operation, the coordinator reserves the family version, stages and verifies artifacts, promotes them, and commits the local version plus publication intent. The publisher sends that frozen payload to the frozen graph destination under a write grant, then verifies exact readback under its read grant. Only then does the UI show the publication as verified. Opening the result replaces the editor draft only with explicit approval. A later snapshot/build/evaluation uses that exact immutable revision and its own budget—not whatever `latest` becomes.

Publication can occur under the operator's explicit preauthorization before they choose to open the result. Draft-only mode never silently takes this path. Full generation/build composition must state its authorized stages up front. Actual success of the robot is not part of generation success.

## Decisions forced by this exercise

- Idempotent submission is not exactly-once provider execution: M02 and M03 deliberately have different recovery outcomes.
- Generation receipt, local commit, graph commit and graph acknowledgement are separate boundaries: M05-M09 cannot be collapsed into one green “done.”
- Revocation ordering must have a defined local release point and separate readback permission: M09-M12 cannot be solved by a generic retry button.
- Frozen client YAML does not freeze remote policy weights: M14 needs identity enforcement or an explicitly weaker claim.
- Single job dispatch does not by itself release a persistent renderer or kill grandchildren: M13/M15 need ownership acknowledgements.
- Old binaries and external edits are outside a cooperative writer protocol: M18/M19 require fail-closed compatibility and a controlled storage cutover.

## Design-level conclusion

The proposed rules give a conservative next action for every case above: progress only from a verified receipt, block on missing authority/evidence, or preserve an unknown outcome for explicit reconciliation. Independent review found no blocking contradictions across M01-M20, I1-I10 and the phase gates. This establishes design consistency for the enumerated traces under the stated assumptions, not proof of implementation. Each row becomes a proposed implementation test; no live inference, publication or simulation was performed during this exercise.
