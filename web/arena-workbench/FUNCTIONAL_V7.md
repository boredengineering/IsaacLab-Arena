## Ownership and seams

- Production App retains one ThemeProvider, QueryClient, ApiClient and RuntimeProvider. Layout choice is a validated `layout=legacy|v7` UI preference; legacy remains default and unrelated query filters/graph-renderer selection survive changes.
- App owns retained editor/query mounts after their first visit. `active` means visible/authorized for new UI effects, not permission to cancel already accepted jobs. Inactive controllers retain nonsecret state while validation/render scheduling, sensitive input and graph/media effects retire. Avoid duplicate active `workspace` IDs.
- EditorView accepts optional `layout`, `active`, and `renderInspector({validation,bindingKey,onFocusSpecification})`. It remains the sole authoring controller or delegates to one extracted hook; two active copies are forbidden. Inspector data must be current session/source/text-owned Validation, never an offline fixture.
- AuthoredInspector provides source-bound projection/selection plus a guarded reviewed-position seam. Editing is limited to the documented explicit root background/table descriptor; exact candidate validation and explicit consent precede Apply. Other fields remain read-only, and no physical-validity claim follows from schema validation.
- WorkbenchChrome is optional presentation only: navigation/session/theme slots and readiness callback. Editor/controller/provider lifetime remains outside the optional import/error boundary, with a usable legacy fallback on failure.
- Neo4jView gains active/effect retirement while retaining independent query inputs and exact submitted results. Layout/navigation cannot submit a query or retarget an accepted request.
- The F2 YAML utility only proves an explicit root numeric source edit. It does not authorize Apply or assert registry/solver effectiveness; current validation, supported editability, exact candidate validation and epoch-bound consent remain required at integration.

- `/library` and durable save/recovery are mounted over the retained editor controller. Library activity does not keep authoring credentials or automatic-render authority active. Source descriptors (`editor-revision:<32hex>`) remain distinct from issued frozen view IDs; only verified current-owner opens update recents. Save/readback does not automatically reopen or publish a revision. Manual numbered research saves bind an explicitly selected verified editor revision, store, family and parent decision; exact research Open is separate and manual publication remains unsupported.

## Browser storage

- `draft-controller.ts` owns retained draft/prompt/recovery state and exact backup baseline; React subscribes through `useSyncExternalStore`. Rendered control tokens, activation generations and runtime/source epochs fence asynchronous replacement. Loading cleanup does not persist content.
- `draft-storage.ts` keeps backups tab-local in `arena.editor.draft.v1`, reads v1/v2 and writes bounded v2 metadata. Conditional write/remove protects observed sibling replacements; unavailable/conflicting/ambiguous storage preserves memory and recovery obligations. Explicit Review/Restore/Discard reconciles them. This is cooperating same-realm ownership, not cross-context atomicity or power-loss storage.
- `library-preferences.ts` and `library-preferences-native.ts` apply pin/unpin/confirmed-Open operations to the latest record in native IndexedDB transactions. Completion—not request success or notification delivery—acknowledges persistence. BroadcastChannel carries refresh hints only. Legacy localStorage references are preserved during migration, never dual-written; memory-only changes are not automatically replayed.
- Preferences contain bounded exact references, not YAML or verified source authority. A confirmed receipt can add history while the catalogue is unavailable, but pin/Open actions still need their normal live source checks. Existing retry records and credential boundaries are unchanged.
- Detailed contracts, failure transitions and rollback limits: [F3 storage design](../../.agents/references/plans/dashboard_cli_workflow_parity/ui-storage.md).
