## 1. Context & Key Invariants
- Dual-runtime decoupled architecture requires running heavyweight simulation (Isaac Sim 6.0 / PhysX) in `isaaclab_arena-latest` and foundation policy daemon in an isolated environment communicating over ZeroMQ `tcp://127.0.0.1:5556`.
- Rather than compiling CUDA extensions in the DevContainer, we adopted NVIDIA's official containerized policy serving model using `nvcr.io/nvidia/pytorch:25.04-py3` (`gr00t-dev:latest`).

---

## 2. Deliverables & Implementations

### A. Solution 1: `docker/run_gr00t_server.sh`
- Created unified CLI helper script supporting:
  - `-m <model_path>` : HuggingFace ID or local checkpoint path
  - `-e <embodiment_tag>` : Embodiment identifier (e.g. `OXE_DROID`, `NEW_EMBODIMENT`, `GR1`)
  - `-p <port>` : Port (default 5556)
  - `-d` : Detached background mode
  - `-k` : Stop / kill running server container
  - `-r` : Force rebuild `gr00t-dev` image
  - `-s` : PyTorch SDPA math fallback (`GR00T_DIT_SDPA_MODE=math`)
- Automatically mounts `$HOME/models` $\to$ `/workspace/pretrained_ckpts` and `$HOME/.cache/huggingface`.

### B. Solution 2: `docker/docker-compose.sim.yml`
- Created declarative multi-container stack with:
  - `gr00t-policy-server`: Official `gr00t-dev:latest` sidecar
  - `isaaclab-arena`: `isaaclab_arena:latest` simulation engine
  - Shared `--net=host`, `--ipc=host`, and GPU reservations.
