# Add model profile contract

Create-only workspace catalogue on the existing Journal; no second Journal, provider call, activation or credential replacement during registration. Authenticated CSRF PUT `/api/model-settings/profiles/{id}` accepts exactly provider, model, request_policy and rejects duplicate raw JSON keys. IDs match `[A-Za-z0-9][A-Za-z0-9_.-]{0,63}`; builtin IDs and the UI sentinel `custom` are reserved. At most 64 user profiles are retained. Identical replay succeeds, differing replay or full capacity is 409 (identical replay still succeeds at capacity). Provider endpoints remain the fixed ENDPOINTS. Model is an ASCII literal bounded to 256 characters. GET model settings publishes `harness-model-profiles/v2` and `profile_creation: create-only/v1`; v1 decoding remains legacy-compatible and never advertises creation.

Policy has exactly api=chat_completions, temperature_mode=configured|omitted, token_limit_parameter=max_tokens|max_completion_tokens, structured_output=json_schema|json_object|omitted, multimodal_output=json_object|omitted, store=false|null (null omits the keyword). Server assigns origin=user_defined, support=unverified, verification=not_checked, revision=1. Builtins cannot be overridden.

Settings selection is explicit and separate from memory-only key save. Freeze exact effective policy (including builtins) in public/private workflow authorization, immutable jobs and worker config; explicit models never normalize. All inference calls use the frozen policy. User-defined output keeps strict raw duplicate/schema validation; non-schema modes include explicit JSON/schema instructions without claiming provider schema enforcement. Readiness remains documented-only.

Screen additions before persistence against active credentials; screen incoming keys against the entire public catalogue before replacement. Grant secret classification permits only exact validated policy paths, not token-name exemptions.

UI uses strict versioned metadata with legacy v1 support, Add -> authenticated readback -> explicit selection -> explicit key save. Display literal identities, unverified status, workspace persistence and memory-only key disclosure. Disable Add without backend capability. Preserve lifecycle/session/query epochs and stale-handler fences. Isolated nonroot network-none RED/GREEN checks only; no live deployment, state or provider requests.
