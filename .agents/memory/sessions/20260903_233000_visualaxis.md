## 1. The Review Caught a Plan That Would Have Given a Wrong Answer

The first draft of the stale-frame test was "set `num_rerenders_on_reset = 1`, re-run, see if success changes". [IsaacLab #6394](https://github.com/isaac-sim/IsaacLab/issues/6394) documents that **the flag does not fix the defect** (~4.96 with 2 rerenders vs ~4.98 with 0). The mechanism is visible in `manager_based_env.py:425-431`: reset calls `_reset_idx`, then `write_data_to_sim()`, then `sim.forward()`, then `sim.render()` — and `sim.forward()` does not step physics, so with fabric the written transforms may not have reached the renderer. Isaac Lab's docs confirm the default is stale.

So the draft test would have flipped an ineffective flag, seen no change, and **wrongly exonerated stale frames**. Replaced with a pixel-space assertion (`d_prev` vs `d_self`) across a flag matrix that includes `disable_fabric`, which targets the root cause rather than the documented remedy.

**Generalisable lesson**: when the remedy for a suspected defect is a config flag, test the defect directly, not the flag. A no-change result conflates "no defect" with "flag does nothing".

## 2. Three Further Corrections from the Literature

- **Cosine-to-centroid is the weakest reasonable OOD score.** Ranking is kNN ≳ Mahalanobis > cosine-to-centroid; cosine-to-centroid *is* Mahalanobis with an identity covariance and the norm discarded ([Sun et al. 2022](https://arxiv.org/abs/2204.06507): kNN FPR95 29.15% vs Mahalanobis 37.94%). Mitigating nuance: in transformer embedding spaces angular and Mahalanobis nearly coincide ([OODformer](https://arxiv.org/pdf/2107.08976), ±2%), so the original choice was suboptimal rather than invalid.
- **20 episodes per condition is indefensible.** Computed for this design: at n=20, Fisher exact cannot resolve 0.90 vs 0.70 (p=0.235); at n=100 it can (p<0.001) but still cannot resolve 0.90 vs 0.80 (p=0.073). Clopper-Pearson at observed 90%: ±15.2 pts at n=20, ±6.4 at n=100. **n=100/arm is now the floor.**
- **Freezing the vision encoder under a domain gap is the disfavoured setting.** [Diffusion Policy](https://arxiv.org/pdf/2303.04137): ViT-CLIP 0.70 frozen → 0.98 fine-tuned. [OpenVLA](https://arxiv.org/pdf/2406.09246) fine-tuned its backbone deliberately. GR00T's `tune_visual=False` default is precisely the frozen setting — so §4's binary table became a four-arm comparison, with observation canonicalisation as a no-training fourth arm.

## 3. A Finding from Implementing the Fix

Building the embedding bank surfaced a limitation of the score the plan had upgraded *to*. **Both cosine scores are blind to a purely radial shift.** Measured: scaling embeddings outward along the mean direction gives AUROC < 0.7 for `cosine_to_centroid` and the L2-normalised `knn_cosine`, and > 0.9 for Mahalanobis and a Euclidean kNN.

That is the "norm removal" weakness made concrete, and it is not hypothetical — an appearance change altering embedding magnitude rather than direction would be invisible to the originally specified score. Fixed by adding `knn_euclidean`, having `is_ood` take the **maximum** over calibrated percentiles, and pinning the limitation in a test so nobody later relies on the cosine scores alone.

## 8. Gate 1 Closed (added 2026-09-04)

**Stale reset frames are real.** Measured, three episodes per config, on a light kitchen scene:

| Config | Verdict | `d_prev` | `d_self` |
| :--- | :--- | :--- | :--- |
| rerenders=0, fabric on (Isaac Lab default) | **2/2 STALE** | **0.0, 0.0** | 6.0, 12.0 |
| rerenders=1, fabric on | fresh | 5.95, 12.17 | 1.74, 2.58 |
| rerenders=2, fabric on | fresh | 6.82, 13.13 | 1.74, 2.22 |
| rerenders=1, fabric off | 2/2 stale | 0.52, 0.40 | 0.58, 0.41 |

`d_prev = 0.0` exactly: the reset observation is **bit-identical** to the previous episode's final frame.

**And my own plan was wrong about the remedy.** §5c.0 asserted, citing IsaacLab #6394, that `num_rerenders_on_reset` does not fix this. On this version it does, cleanly. The methodological point survives — measuring in pixels is what established both the defect *and* the working fix — but taking the issue report on trust would have sent us patching the simulator instead of setting a flag. **Lesson: a bug report is evidence about someone else's configuration, not a measurement of yours.**

Fixed in `arena_env_graph_conversion_utils.build_arena_env_from_graph_spec`, which now forces `num_rerenders_on_reset >= 1` for every generated environment. The maple v9 env was running in the confirmed-stale configuration.

**Scope of the damage**: any measurement taken from the *first* frame of an episode in a generated env was taken on the previous episode's image. Scene-geometry findings are unaffected; claims about what the policy saw at step 0 are not.

Four incidental things found while getting the test green, each a real gap rather than test noise:
- `progress_tracker.py:318` mutates state tensors in place during `reset()`, so a reset outside `inference_mode` after steps taken inside it raises "Inplace update to inference tensor". Callers must keep one mode.
- `PickAndPlaceTask` needs a **rigid** destination; a background asset raises "Contact sensor is only supported for rigid objects".
- Embodiment cameras need `enable_cameras=True` on the embodiment, not just the app launcher.
- `disable_fabric=True` appears to suppress camera updates entirely rather than fix ordering. Not a remedy.
