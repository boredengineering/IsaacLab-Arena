## 1. Architectural Decisions

1. **Closed diagnose → patch → re-evaluate loop**:
   - `eval_self_healing.py` holds `EvaluationDiagnosticOracle.diagnose_eval_run()` → `list[FailureSignature]`, and `EvaluationRemediationEngine.remediate_and_heal()` → patched spec + policy YAML.
   - Single entry point: `environment_generation_runner.py --mode auto_heal --env_name <env>`.

2. **Three healing modes** (`--healing_mode`):
   - `deterministic` — statistical/spatial rule oracle over the Markov stage funnel.
   - `llm` — generative reasoning via OpenRouter with a strict JSON schema.
   - `hybrid` (default) — deterministic first, LLM only when no rule fires and `success_rate < 0.8`.

3. **Defect taxonomy (v1, string-keyed)**: `camera_occlusion`, `in_flight_slip_inertia`, `unconditioned_vla`, `horizon_truncation`, `depth_alignment_mismatch`.

4. **Semantic versioning + dual ledger**:
   - `generated_envs/<env>/v1..vN` with a `latest` symlink; `eval_output/<env>/vN` mirrors runs.
   - `lineage.json` (agent/human readable) and `lineage.ttl` (PROV-O) updated automatically by `policy_runner.py` on rollout completion, plus Neo4j sync.

5. **Sim-to-real invariant established**: never inflate USD `physics_material` friction to force success. Remediation must act on the controller, policy config, or layout — real fruit friction cannot be edited.
