# Dashboard evaluation/build/healing/operator parity audit

## Scope and conclusion

Static, read-only audit of `/workspaces/IsaacLab-Arena`, branch `dev/0.3.0-prerelease`, observed HEAD `af6774ec6`. Read the root README, agentic-example README, requested four RST pages, CLI/runtime definitions, workbench API/dispatcher/storage/frontend, and bounded DCRG contracts. No application execution, tests, network, service inspection/start/stop, jobs, or live credentials were used. Existing dirty graph-explorer changes were left untouched. This report is the only file written, outside the checkout.

**The dashboard is an authoring/snapshot workbench, not a policy-evaluation frontend. A from-scratch toggle alone cannot deliver CLI parity.** It needs separate, typed workflows for build/zero-action preview, real policy evaluation, experiment batches, diagnosis/remediation, bounded evidence-driven refinement, publication/provenance, and operator recovery. Existing cancellation, immutable-input jobs, authenticated artifact serving and conservative restart behavior are useful foundations, not proof those workflows already exist.

Root README is not the complete branch capability contract: `README.md:88-94,116-122` advertises zero-action smoke/Kit runs, `:161-163` builder controls, `:174-180` separate IL/RL workflows, while `:221` still describes agentic generation as unimplemented. `pyproject.toml:5-10` declares 0.3.0, versus root README's 0.2.x labeling. The local agentic README explicitly says evaluation is separate (`isaaclab_arena_examples/agentic_environment_generation/README.md:3-6,393-405`). This audit does not claim coverage of full training/data-generation UI parity beyond the requested evaluation/build/healing scope.

## 2. What the current workbench actually guarantees

- **Execution allowlist:** supervisor dispatches only `diagnostic`, `generate`, `snapshots` (`API/supervisor.py:42-57`). Editor capabilities expose generation/snapshots/Neo4j, not evaluation/build/healing (`API/editor.py:64-86`). No registered evaluation adapter is hidden behind the job UI. Route composition is explicit (`API/application.py:152-157`).
- **Durable immutable commands:** SQLite WAL/FULL, transactional job/event writes, immutable fingerprint and workspace-wide idempotency (`CORE/workbench/journal.py:30-66,98-132,150-160`). Same workspace/key + same body returns existing job, changed body conflicts. Default shared pending cap is 32 across queued/running/cancel_requested jobs, not a per-kind or GPU-hours budget. `snapshot()` returns jobs/cursor but not `queue_paused` (`:211-216`). Journal transition itself does not enforce a legal state-transition graph (`:155-160`); new adapters must not assume it does.
- **One executing job at a time:** serialization is real (`API/supervisor.py:42-58`). Snapshot worker is reusable and keeps its cross-clone host-backed GPU lease for its entire lifetime (`API/snapshot_process.py:30-35,64-66,89-148`). A completed snapshot job can leave a warm simulator holding that cooperative lease. A future policy adapter must explicitly hand off/release it; simply enqueueing evaluation after snapshots is insufficient. This lock is not a scheduler for arbitrary external GPU consumers.
- **No browser lifecycle ownership of jobs:** refresh/reconnect/stream disconnect do not cancel or rerun work. `WEB/editor-jobs.tsx:11-57,60-88` retains ambiguous requests/accepted IDs in per-tab sessionStorage, disables mutation retry, and reads back cancellation status. Discard only removes local retry metadata (`:75-85,105-111`).
- **Cancellation:** queued → cancelled without execution; running → cancel_requested; terminal requests return current state (`API/jobs.py:83-90`). Supervisor records intent before SIGTERM to its owned group; snapshots close their owned renderer (`API/supervisor.py:132-154`). Generation/snapshot final cancellation is committed after cleanup (`API/editor_execution.py:103-114`). Do not render “cancelled” upon button click, and do not equate client-process death with revoking already-sent remote inference.
- **Restart:** interrupted running/cancel_requested jobs become `indeterminate`, never automatically replayed; unclean shutdown/active interruption pauses the queue durably (`CORE/workbench/journal.py:162-181`). Recovery reaps only stored process identities (`API/process_identity.py:13-31`). Explicit resume unpauses the shared queue (`API/jobs.py:75-80`), not just diagnostic tests; UI's misleading diagnostic placement is acknowledged in `EG/README.md:440-444`. Missing: visible pause reason, preview of all affected jobs, selective/fair resume/admission, evidence-based resolution for indeterminate evaluation, drain/maintenance operation.
- **Progress:** SSE carries durable job events, not simulator pixels (`API/events.py:36-69`); replay gaps require a fresh snapshot. Current event admission is eight streams, heartbeat 15 seconds, max lag 256; journal retains an expired-prefix policy protecting recent/active events (`CORE/workbench/journal.py:218-247`). Preserve a read-only observation channel and never make polling launch work.
- **Generation budget:** isolated process wall limit 180 seconds (`API/generation.py:17`, `editor_execution.py:132-178`), 45-second SDK timeout, max eight completion calls including initialization, SDK retries zero (`provider_security.py:59-88`), agent max_tokens 4096/max_retries 1 (`generation.py:86-87`). These are not a dollar budget, total input-token cap, provider-side refund, or per-workspace spend quota. Result currently retains YAML/schema/allowlisted stages/publication/warnings only, losing detailed cost and prior provenance (`generation.py:99-116`; `editor_execution.py:179-187`).
- **Credentials:** temporary references are rebound neither on queued dispatch nor startup races; provider/model identity checked twice before private-pipe authorization (`API/editor_execution.py:120-163`). Settings changes cannot silently migrate a pending job to another credential. Session revoke forgets credential, not jobs (`API/security.py:81-92`). Already released remote requests cannot be retracted. No real credentials were inspected here.
- **Important from-scratch prerequisite:** generation subprocess environment allowlist excludes `NEO4J_*` (`API/provider_security.py:107-110`), while `CORE/lpg_neo4j_sync.py:19-45` resolves connection from those variables and `environment_generation_agent.py:185-197` constructs its own retriever and silently degrades to no priors via traces. A healthy API-side Neo4j query does not prove worker access. Solve trusted retrieval/credential delegation and record the exact prior receipt; do not pass arbitrary database credentials through durable job inputs or the browser.

## 3. Zero action, actual policy, snapshots, Kit, video and streams are different

1. **Schema:** `CORE/workbench/documents.py:207-221` only validates schema and explicitly warns it does not certify stability/task success.
2. **Snapshots:** one environment, zero action steps; scene and individual authored-pose USD captures. Six-minute snapshot deadline includes render-lease wait/startup/RPC, not time spent queued before dispatch (`API/snapshot_service.py:117-169,197-210`). Partial asset results may still produce a succeeded job with `partial: true`/errors (`:231-291`). This must remain visible, not a green all-assets-pass badge.
3. **Build/zero-action rollout:** relations and physics are exercised, but no learned policy is evaluated. Literal zeros are not neutral for every action space; G1 uses absolute joint and pelvis targets (`EVAL/policy_runner.py:87-127`). The build runner's simple zero policy has different settling behavior from the policy runner (`EG/environment_generation_runner.py:696-720`).
4. **Policy rollout:** `policy.get_action` is actually called (`EVAL/policy_runner.py:502-505`). Settling is separate simulation work: at least 50 allowed settle steps with an early-stability check after step 40, potentially again after resets (`:160-203,525-537`); these are not counted in the requested policy step loop. A settle termination rejects the rollout, but merely exceeding speed thresholds only warns and proceeds (`:169-182,239-249`). Display this distinction. Requested episode counts can be exceeded by simultaneous vector-env terminations (`:509-521`); exact-count evidence adapters must reject rather than truncate.
5. **Kit local visualizer:** `--viz kit` is an operator desktop/host display, not a dashboard iframe. AppLauncher owns visualizer selection; `--headless` is deprecated and overrides visualizers; `--viz none` explicitly disables them (`submodules/IsaacLab/source/isaaclab/isaaclab/app/app_launcher.py:489-529,811-880`). Availability depends on installed runtime backends/display permissions, not just an option in a form.
6. **Isaac livestream:** separate AppLauncher `--livestream {0,1,2}`, not an invented `--viz stream`. WebRTC modes enable extensions and force host-headless execution; public mode configures public IP and ports 49100/47998 (`app_launcher.py:753-807,838-843`). It needs separately reviewed routing/exposure, leases, authentication, attach/detach/stop semantics and disconnection policy. Not wired into dashboard.
7. **Recorded viewport video:** MP4 from `env.render()`/RecordVideo, third-person scene view. **Recorded camera video:** independent MP4s from `obs['camera_obs']`, per-episode/per-env camera evidence. Neither is SSE nor a live view (`isaaclab_arena/video/video_recording.py:16-40,86-106`; `EVAL/experiment_runner_cli.py:31-41`). Preserve camera names, episode/frame mapping, transforms used by policy, and actual effective cameras; do not claim a scene screenshot is what the policy saw.
8. **Critic output:** build calls `evaluate_scene_spec(loaded_spec)` without images or backend (`EG/environment_generation_runner.py:668-691`). VLM tiers require images (`CORE/visual_critic.py:82-125`); normal build therefore uses heuristic geometry/advisory, not image inspection. Advisory fallback returns `conforms=True` and score 8.0 despite bypassed verification (`:302-318`). Dashboard must label tier/skipped/advisory explicitly. `PhysXPreflightCritic` also checks authored Z heuristics, not a simulation (`:322-354`).

## 4. Evaluation and healing evidence/provenance gaps

### Required immutable evaluation record

Freeze the source YAML + includes + raw-source hash, canonical spec hash, repository/runtime/renderer/asset revisions, effective builder/variation settings, requested and actual seed/env/episode counts, task and hand/frame contract, policy type and full effective config hash, checkpoint identity and verification source, remote endpoint profile, modality/action mapping/horizon, language instruction, recording options, settle settings, execution/cleanup status, and all artifact IDs/digests. Store output ownership paths server-side; give the browser opaque IDs.

Current saved editor revisions already retain source, includes and canonical identity without overwriting repository YAML (`CORE/workbench/documents.py:224-255`). Current snapshots record canonical/cache/renderer/options/freshness identities and authenticated PNG IDs, with bounded file checking (`API/snapshot_service.py:98-107,276-300`; `API/editor.py:260-269`). Reuse these contracts, but add a general artifact manifest/media API: current artifact route serves PNG only, not JSONL/HDF5/RDF/MP4/HTML reports.

Policy runner currently writes per-rank `episode_results_rank*.jsonl`, directs recorder HDF5 to its run directory, optionally records both videos, writes telemetry and report (`EVAL/policy_runner.py:70-84,667-700,734-784`). Reach JSONL records named object/destination/body frame (`policy_runner_cli.py:159-192`; runner `:252-443`). Dashboard has no scoped artifact/results importer or evaluation detail view.

### Current CLI inconsistencies to avoid baking into the UI

- Versioned successful resolve actually uses `EnvironmentVersionManager`, whose defaults are fixed container paths under `generated_envs`/`eval_output`, not the RST's advertised simple `<out_dir>/<name>.yaml` (`EG/environment_generation_runner.py:289-311`; `CORE/version_manager.py:54-68`). `out_dir` still affects invalid output and some intermediate/healed files. Present effective destinations explicitly.
- Version creation can scaffold GR00T policy YAML from embodiment, updates `latest` and mutable JSON/RDF ledger, and is not a transactional multiwriter publication system (`CORE/version_manager.py:147-250`). Existing `evaluation` entry is overwritten on a later evaluation for the same version (`:252-280`). Do not use it as a lossless run history or blindly expose an untrusted family-name/path writer.
- Generated README commands hardcode runtime name/paths/port, broaden X11 access, and their benchmark gives both `num_steps` and `num_episodes` (`CORE/version_manager.py:467-529`). In current policy-runner main, policy intrinsic length wins; otherwise steps win over episodes (`EVAL/policy_runner.py:683-697`), while `rollout_policy` and typed `RolloutLimitCfg` require one (`:460-461`; `EVAL/arena_run.py:35-40`). UI should reject ambiguity and show effective limits, not copy generated commands verbatim.
- Legacy policy telemetry uses a second-resolution run ID and policy-class string as `modelWeightsPath`, not served weights; environment link is resolved from registered name or YAML filename, not immutable spec hash (`EVAL/telemetry_to_prov.py:163-178`; `policy_runner.py:572-597,739-747`). Collision-free job/run IDs and explicit identity provenance are needed.
- Policy telemetry is emitted only when metrics exist; Neo4j failure is a warning after local RDF write, not rollout failure (`policy_runner.py:734-780`; `telemetry_to_prov.py:255-271`). Both agent and CLI can attempt spec publication (`CORE/environment_generation_agent.py:367-376,560-569`; runner `:313-331`), and CLI extra publication exceptions are swallowed. Do not infer publication from process exit or generation success.
- Experiment outputs differ: `episode_results_rebuild*.jsonl` (`EVAL/run_execution.py:107-109`) versus policy-runner rank files. Report parser supports both (`isaaclab_arena/visualization/report.py:24-26`), but legacy auto-heal reads only rank files (`CORE/eval_self_healing.py:94-124`). Experiment orchestration also does not call the policy-runner main's PROV/lineage tail (`EVAL/experiment_runner.py:135-152`; `run_execution.py:97-128`). A common evidence adapter/publication step is missing, not just a frontend panel.
- `summary_metrics.json` is expected by auto-heal (`CORE/eval_self_healing.py:74-92`) but the inspected production evaluation modules do not write it; a repository source search found that filename in the oracle, a test fixture, and version-manager documentation only. Without JSON the oracle's TTL fallback only recognizes selected zero-valued strings, then defaults missing success/movement to zero. Missing metrics must become unknown/insufficient evidence, not fabricated zero-success diagnosis.
- Auto-heal can choose latest version's eval directory or globally newest `eval_output/*/*`, and defaults policy config independently (`EG/environment_generation_runner.py:432-480`); parent is manager latest rather than necessarily the explicitly selected base (`:542-549`). Explicitly bind evaluation, spec version and policy config; never silently heal another run.
- Auto-heal uses a guessed executed step count (`runner:487`), unrestricted signature dictionaries and writes patched policy YAML into `out_dir` before validating all spatial changes (`CORE/eval_self_healing.py:683-745`). May change table/robot pose/object sectors and controller hyperparameters. Validate/allowlist patch keys, freeze semantics and provide diff approval; “same-scene policy comparison” cannot include unmarked scene changes. Missing policy path can reach `Path(None)` (`:673`; runner default resolution `:470-480`).
- Hybrid diagnostic fallback is only invoked if deterministic signatures are empty and success is below 0.8; LLM mode can make paid calls, and its backend initialization precedes its catch block (`CORE/eval_self_healing.py:357-393,452-469`). Do not promise all auto-heal modes are offline or bounded by current workbench generation budgets. Planner output is explicitly reporting-only, not what selects the applied remediation (`runner:495-498`). Auto-heal does **not** run the recommended next rollout (`runner:524-582,748-750`).
- Standalone policy runner has a legacy `is_remote → shutdown_remote(remote_kill_on_exit)` tail but no general `policy.close()` call (`EVAL/policy_runner.py:722-730`). GR00T/OpenPI inherit `PolicyBase.is_remote=False` (`isaaclab_arena/policy/policy_base.py:67-70`) and implement client-only `close()` (`isaaclab_arena_gr00t/policy/gr00t_remote_closedloop_policy.py:311-327`; `isaaclab_arena_openpi/policy/pi0_remote_policy.py:139-145`). Experiment runner uses `close_run_resources` in finally (`EVAL/run_execution.py:121-122`; `resource_cleanup.py:23-50`). New workbench workers need verified client/env/process-group cleanup on all exits; do not activate the stale managed-server branch or kill independently served models.
- Standalone `--serve_evaluation_report` blocks after evaluation and binds `0.0.0.0` (`isaaclab_arena/visualization/report.py:284-300`); its default 8000 conflicts with documented OpenPI port. Prefer authenticated artifact/report viewing through the existing origin, not auto-launching an unbounded report server per job.

### DCRG is the stronger bounded-loop contract, not generic auto-heal

DCRG freezes actual-policy label, scenario/hand, seeds, config digest and Kit args; remote diffusion seed remains null (`EG/dcrg_runner.py:93-110`). It separately bounds candidates/iterations and per-seed simulator timeout, excludes baseline from candidate count, requires exact episodes, and permits only tightly validated target XY movement (`DOC/dcrg.rst:76-100`; `CORE/dcrg/loop.py:219-243,283-307,350-373`). Acceptance compares matched-count task/lift scores; stopping success requires a success on each of at least two distinct seeds (`:259-281`), not every episode succeeding and not statistical robustness.

Immutable spec/evidence receipts and graph outbox events permit resume without rerunning completed evaluations; started-without-evidence is indeterminate (`:219-243`). Graph-sync failures are persisted and propagate; pending/failed events are retried on resume (`:329-347`). Unlike legacy best-effort graph publication, sync failure can make DCRG status failed with valid local evidence still retained. UI must distinguish outcome, controller terminal reason, and sync status.

DCRG rollout subprocess uses `subprocess.run(timeout=...)`, records manifest/log/digests/episode evidence, but does not itself implement workbench's owned process-group cancellation (`CORE/dcrg/evaluation.py:178-229`). It must be integrated as an owned cancellable adapter before exposing “Stop refinement”; killing just the parent or treating CLI timeout as complete descendant cleanup is insufficient.

## 5. Trust boundaries and operator parity

- **Current trust:** single-operator shared default workspace, not multi-user tenant isolation. Sessions are browser authorization/CSRF boundaries, not Docker identities. Jobs/list/cancel/resume are workspace-wide (`API/jobs.py:43-90`; `CORE/workbench/journal.py:98-109`). Exact Host/Origin checks, HttpOnly SameSite cookie and CSRF are present (`API/application.py:128-146`; `security.py:26-55`). Do not expose this as internet-safe multi-user management.
- **Typed executor boundary:** CLI permits arbitrary policy imports (`EVAL/policy_runner.py:39-61`), environment class paths, filesystem outputs and Kit args. Browser HTTP must use fixed server-side adapters, registered profiles, bounded numeric controls, immutable config IDs, and vetted artifacts/endpoints; never shell strings, arbitrary import paths or raw Docker arguments.
- **Dependency readiness is layered:** API health is hardcoded generation/preview false, whereas editor capabilities calculate separate settings/adapter availability (`API/application.py:148-150`; `editor.py:64-85`); Neo4j capability is assigned true without a connection proof (`application.py:115`). Distinguish feature installed, configured, reachable, protocol-compatible, checkpoint-verified and fresh inference-tested. No health polling may download models or perform billable inference without authorization.
- **External policy servers:** GR00T docs launch weights/server separately and warn first start downloads weights (`DOC/eval_with_gr00t.rst:14-25`). OpenPI launcher can build image, download checkpoint/cache, use all GPUs and host network, and recursively restore cache ownership on exit (`isaaclab_arena_openpi/docker/run_openpi_server.sh:47-95`). Those are privileged, costly side effects, not connection probes. A future managed-server action requires explicit owner/profile/host path/image/checkpoint/GPU/ports/storage/budget approvals and must refuse shared/unowned servers. Current policy `close` should leave server alive.
- **Launcher scope:** read-only inspect/config/status versus explicit start/stop; start only workbench frontend/API, no dependencies; collision checks and rollback preserve dependencies (`docker/workbench/workbench.py:286-355`). Runtime stop uses verified identity + pidfd, with no unsafe PID fallback (`docker/workbench/runtime.py:99-120`). Existing API socket preflight rejects any existing socket (`:172-176,204-211`), preventing the API's guarded stale-socket path (`API/runtime.py:84-131`). Supported stale recovery, dependency credential provisioning, safe drain/restart, and a comprehensible queue resume remain gaps.
- **Publication trust:** graph queries are not graph writes; model/simulator outputs should enter immutable artifact storage before explicit publication. Publication can be partial across revision files, local RDF, ledger and Neo4j. Require destination-level receipts and idempotent sync; retrying publication must not re-run inference/evaluation. Save draft, publish generated candidate and publish measured evidence must be distinct actions.
- **Future distributed boundary, not cluster implementation:** keep backend-neutral job/attempt IDs, versioned frozen commands, capability/resource requirements, phase events, cancellation intent/receipt, artifact manifest and publication outbox. Current SQLite/UDS/flock/session/host-path assumptions are local, not distributed leases or multiworker scheduling. Policy CLI supports torchrun rank/device/seed mapping (`EVAL/policy_runner.py:609-658`); experiment parser explicitly rejects distributed (`experiment_runner_cli.py:111`). Do not claim broad distributed experiment parity or implement a cluster to fix local dashboard gaps.

## 6. Acceptance cases for the implementation plan (not executed)

Each case must be backed by real execution when separately authorized; static/UI tests alone cannot prove model or simulation outcomes.

1. **No-work browsing:** open/reload editor, saved results, graph explorer, catalogue, service statuses and event stream; no model calls, builds, GPUs, downloads or publications occur. Existing dirty graph rendering/layout controls remain non-mutating and intact.
2. **Source identity:** submit loaded YAML with frozen includes, then edit source/include in another tab; running job retains original bytes and canonical hash. Selecting a newer document cannot mutate an older job. Save/export never overwrites repository source.
3. **Prompt-first vs refinement:** mode change produces genuinely different API input contract. From-scratch omits base and implicit document load; refinement records base hash. Record prior IDs, deciding eval IDs/counts/policy and exact retrieved content hash, or explicit empty/error reason; a graph-priors-loading stage alone is not proof.
4. **No blind publication:** generation result defaults draft-only, allows review, and records schema/semantic/geometry status separately. Explicit publication produces verifiable destination receipts. Simulate graph outage: preserve local result, show failed sync, retry only sync without another model call/version duplication.
5. **Build/preview parity:** valid YAML → relation solve → requested bounded zero-action steps across allowed env count/spacing; before/after images are tied to new job ID/spec/options. Zero-step snapshots stay separate; partial/historical assets remain labelled. G1 zero-action versus neutral settle behavior is explicit.
6. **Real policy preflight:** supported GR00T/OpenPI profile checks effective cameras, action shape/horizon/modality, instruction, endpoint and checkpoint provenance. Ping success but incompatible ndarray transport is blocked/diagnosed; a real inference check requires separate authorization and is not manipulation success.
7. **Frozen evaluation config:** persist effective mutually exclusive steps/episodes, intrinsic-policy-length behavior, seed/placement seed, variation map, rebuilds, settle budget, device and videos. Report requested versus actual completed count and uncontrolled remote diffusion seed. Invalid/unbounded input is rejected before starting a worker.
8. **Budget:** wall timeout includes startup/inference; enforce per-run and experiment/candidate totals with accounted settle work, retry calls, output bytes and admission limits. Exhaustion stops further children and leaves partial evidence. Expose actual counts/tokens where available; do not fabricate cost or percent complete.
9. **Results are not pass badges:** inspect N=0, failed launch, settle termination, partial episode, nonfinite data, success with zero physical progress, sustained lift without placement, and full success. Unknown rates remain undefined; separate job succeeded, valid evidence, task success and controller acceptance. Never discard extra episodes to meet a denominator.
10. **Artifacts:** current job-bound JSONL/HDF5/reach/RDF/viewport MP4/policy-camera MP4/report have manifest IDs/digests and valid authenticated downloads; raw paths, secrets and untrusted executable HTML cannot escape. Old cached images/videos cannot satisfy a fresh-job criterion. Decode videos and correlate episodes when runtime verification is authorized.
11. **Experiment parity:** run documented legacy JSON and typed YAML paths; variation overrides, rebuild episode splitting, continue-on-error and stop-on-error behave explicitly. Failed/unattempted/skipped children are visible. Chunked legacy mode must not pretend all chunks share one output directory; no duplicate aggregation of per-seed and aggregate records.
12. **Queue/reconnect:** accepted response lost → retry same key yields original job; same key/different inputs conflicts. Refresh, SSE gap, polling, session expiry and tab closure cause no redispatch. Recovery snapshot carries accurate cursor and visible queue pause state; resume lists all affected work, not “tests” only.
13. **Cancellation:** cancel queued, startup, active inference, native Kit hang, between rebuilds, between candidates, and publication phase. Parent and owned descendants are reaped before resource release/terminal acknowledgement. Remote independently managed model server and unrelated GPU jobs remain alive. Late receipts cannot convert cancelled work to success; already-sent requests are disclosed.
14. **Restart/indeterminate:** API crash marks active work indeterminate, keeps queued work paused, and verifies exact worker identity before cleanup. Completed evidence may be reconciled without new rollout; no receipt means no automatic retry. Credential loss/replacement blocks queued authorization without silently substituting server fallback.
15. **Auto-heal evidence pairing:** explicitly choose an evaluation whose spec/policy identity matches the selected base. Missing metrics, wrong rebuild filename or invalid artifacts block diagnosis rather than imply zero success. Deterministic mode makes no LLM call; hybrid/LLM show inference budget/consent. Review and validate policy/scene diffs, save a new child of the selected base, and require separate evaluation approval.
16. **DCRG:** baseline reuse verifies source/config/hand/seed/exact-count evidence; allowed XY bounds reject scene/physics/task-gate changes. Resume same contract reuses evidence/outbox; changed contract requires new run. Preserve rejected candidates, sync failures and exhaustion. Accepted lift improvement remains distinct from task success and controller completion.
17. **Viewer lifecycle:** Kit is local display, WebRTC is explicitly leased separately, recorded videos are artifacts, SSE is status. Browser disconnect follows declared attach/detach policy without killing job. No implicit report listener on 0.0.0.0 or conflicting OpenPI port; no arbitrary remote stream URL/command injection.
18. **Operator management:** read-only inspection cannot start dependencies. Start/restart/stop applies only to verified owned service/profile with explicit resource/network/download consent; shared services and persistent volumes untouched. Stale/live/foreign socket and PID-reuse cases refuse unsafe cleanup. Stopping frontend, API, renderer, policy client, policy server and Arena are distinct operations.

## Remaining uncertainty

Findings are source-grounded, not runtime reproductions. No assertion here establishes current service availability, real model credentials, successful inference, physical validity, live browser parity or test pass status. Historical verification sections in the READMEs/RSTs are documentation claims, not fresh audit evidence. Exact resource ceilings, server attestation protocol, report-media security policy, publication defaults and distributed storage/authentication remain design decisions requiring explicit approval before implementation.
